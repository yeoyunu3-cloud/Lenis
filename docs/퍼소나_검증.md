# 퍼소나 시뮬레이션 결과

개발서의 퍼소나 3명이 되어 실제 화면을 휴대폰 크기(375×812)로 사용해 본 기록입니다.
**실제 사용자 조사가 아닙니다.** 화면 동작과 경로 계산만 확인했고, 체감 부담은 인터뷰와 현장 검증으로 확인해야 합니다.
경사는 30m 고도 자료(FABDEM)로 추정한 값입니다.

## 퍼소나 A: 박지연 (34세, 유아차, 초량동)

상황: 집에서 병원까지 유아차로 갔다가 귀가한다. 집은 초량6동 주민센터, 병원은 새부산병원으로 가정했다.

| 방향 | 경로 | 거리 | 시간 | 가파른 오르막 | 가파른 내리막 |
|---|---|---|---|---|---|
| 갈 때 | 최단 | 450m | 7.5분 | 0m | 227m |
| 갈 때 | **유아차 맞춤** | 615m | 10.3분 | 0m | **141m** |
| 귀가 | 최단 | 450m | 7.5분 | 227m | 0m |
| 귀가 | **유아차 맞춤** | 668m | 11.1분 | **88m** | 0m |

- 해결됨: 가파른 내리막과 오르막을 방향별로 비교하고, 갈 때와 귀가 경로가 다르게 나온다.
- 미해결: 병원의 접근 가능한 출입구를 안내하지 못한다. 출입구 데이터가 없다.
- 미해결: 턱과 좁은 보도는 데이터가 부족해 경로에서 충분히 걸러지지 않는다.

## 퍼소나 B: 이민준 (25세, 여행용 캐리어, 관광객)

상황: 부산역에 도착해 언덕 위 목적지로 이동한다. 목적지는 초량6동 주민센터로 가정했다.

| 경로 | 거리 | 시간 | 가파른 구간 |
|---|---|---|---|
| 최단 | 813m | 13.6분 | 311m |
| **캐리어 맞춤** | 1017m | 16.9분 | **88m** |

- 해결됨: 204m 더 걷는 대신 가파른 구간이 223m 줄어든다는 판단 근거를 바로 보여 준다.
- 해결됨: 더 편한 길이 없는 구간(부산역 → Kimchee Guesthouse)은 없다고 안내한다.

## 퍼소나 C: 김영희 (68세, 장보기 손수레, 주민)

상황: 초량전통시장에서 장을 본 뒤 초량6동 주민센터 쪽 집으로 귀가한다.

- 미지원: 손수레 유형은 개발서의 추후 확장 범위라 앱에서 고를 수 없다.
- 참고: 유아차 기준으로 계산하면 최단 534m(가파른 구간 227m), 맞춤 715m(88m)이다. 손수레 결과로 쓰면 안 된다.

## 시뮬레이션에서 찾아 고친 문제

| 문제 | 영향 | 수정 |
|---|---|---|
| 장소 이름을 입력하면 아무 반응이 없음 | 사용자가 길을 찾을 수 없음 | 초량 장소 77곳 검색, 못 찾으면 안내 문구 |
| 추천 구간을 누르면 고른 이동 유형이 바뀜 | 캐리어 사용자가 유아차 결과를 봄 | 고른 유형 유지 |
| 제보 위치를 안 고르면 도착지로 저장됨 | 장애물 위치가 틀리게 쌓임 | 위치를 고른 뒤에만 저장 |
| 결과 화면에서 지도를 누르면 출발지가 바뀜 | 지도를 움직이다 경로 정보가 어긋남 | 길 찾기 화면에서만 지정 |
| 최단 경로와 맞춤 경로가 같아도 카드가 2개 | 다른 길로 오해 | 카드 1개와 안내 문구 |
| 어떤 길이 나은지 바로 알기 어려움 | 카드를 모두 비교해야 함 | 맨 위에 추천 문장 표시 |
| 가파른 길의 방향을 구분해 볼 수 없음 | 내리막 부담을 판단하기 어려움 | 가파른 오르막·내리막 따로 표시 |

## 남은 과제

1. 시연 목적지의 접근 가능한 출입구 조사
2. 실제 보호자·캐리어 이용자 인터뷰로 퍼소나 가설 검증
3. 네이버지도 경로 비교 입력 (`docs/네이버_경로_입력.json`)
4. 실제 휴대폰에서 접속 확인
