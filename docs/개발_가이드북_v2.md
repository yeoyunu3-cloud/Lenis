## 0. 한눈에 보기

### 무엇을 만드나

```
                 ┌──────────── AI ① 장애물 탐지 (YOLO) ─────────────┐
 Mapillary 사진 ─┤  계단·턱·경사로를 사진에서 찾음 → 지도 위 위치로 저장  │
                 └───────────────────────────────────────────────┘
                                         │
 OSM 도로망 + 계단 427곳 ─┐              ▼
 DEM 경사도 ──────────────┼──→ 구간별 장애물·경사 지도 ──→ AI ② 사진 없는 구간 예측 (XGBoost)
 이용자 제보 ─────────────┘                                  │
                                                             ▼
                                   유형별 통과 판정 → 경로 2~3개 + 출입구 안내 (웹/앱)
```

### AI가 두 개다

| | AI ① 장애물 탐지 | AI ② 사진 없는 구간 예측 |
|---|---|---|
| 모델 | YOLO11 (객체 탐지) | XGBoost (분류) |
| 입력 | 거리 사진 | 구간의 경사·길이·주변 정보 |
| 출력 | 계단·턱·경사로 박스 + 확신도 | "이 구간에 계단이 있을 확률" |
| 학습 데이터 | 공개 데이터셋 + 부산 사진 직접 라벨링 | OSM 계단 427곳 + AI ① 결과를 정답으로 |
| 왜 필요 | 지도(OSM)에 없는 장애물을 찾음 | 사진이 없는 골목도 판단 |
| 포스터 문구 | "AI가 사진에서 계단·턱 탐지" | "AI가 안 가본 길까지 판단" |

> AI ②가 있어야 포스터의 "안 가본 길까지 판단"이 사실이 된다. 시간이 부족하면 AI ①만으로도 데모는 된다 (9장 참고).

### 사진은 직접 찍지 않는다

공개 데이터만 쓴다. 단, **부산 Mapillary 사진 200장에 박스를 직접 그리는 라벨링 작업**은 한다 (3-2 참고). 찍는 게 아니라 이미 있는 사진에 표시만 하는 것.

## 3. AI ① 장애물 탐지 (YOLO) – 담당 A

### 3-1. 클래스 정하기 (11/6)

`ai/config.py`의 `CLASSES`를 **3개로 줄인다**: `["stairs", "curb", "ramp"]`

- `elevator`는 거리 사진에 거의 안 나와서 학습이 안 된다 → 출입구 데이터(OSM, 공공데이터)로 처리.
- 포스터의 "3종"과도 맞는다.

### 3-2. 데이터 모으기 (11/6 ~ 11/10)

**① 공개 데이터셋 (학습용)** – `data/raw/<이름>/`에 YOLO 형식으로 받기

| 클래스 | 목표 박스 수 (train) | 찾을 곳 |
|---|---|---|
| stairs | 1,500 이상 | Roboflow `stairs`, [staris](https://universe.roboflow.com/ine-4jp8h/staris), AI Hub 인도보행 |
| curb | 1,000 이상 | Roboflow `curb`, `kerb` |
| ramp | 500 이상 | Roboflow `ramp`, `wheelchair ramp` |

- 받을 때마다 `docs/데이터_출처.md`에 한 줄 기록 (이름·링크·라이선스·장수).
- 클래스 이름이 다르면 `config.py`의 `NAME_MAP`에 추가 (예: `"staircase": "stairs"`).

**② 부산 사진 직접 라벨링 (검증용, 가장 중요)**

공개 데이터셋은 외국 사진이 많다. **부산 사진에서도 잘 되는지** 따로 확인해야 심사 질문에 답할 수 있다.

1. `03_fetch_mapillary.py`로 받은 부산 사진 중 **200장**을 고른다 (계단·턱이 보이는 사진 위주 150장 + 아무것도 없는 사진 50장).
2. Roboflow 무료 프로젝트에 올리고 4명이 50장씩 박스를 그린다 (Roboflow Annotate).
3. YOLO 형식으로 내보내서 `data/raw/busan_labeled/`에 둔다.
4. **이 200장 중 100장은 시험용(test)으로만 쓴다.** 학습에 섞으면 점수가 부풀려진다.

> 코드 수정 필요: `01_merge_datasets.py`가 `busan_labeled`의 test 100장은 무작위 분할에서 빼고 항상 test에 넣도록. (Claude Code에 "busan_labeled 폴더는 절반을 고정 test로 쓰게 01_merge_datasets.py 고쳐줘")

### 3-3. 학습 실험 (11/10 ~ 11/17) – Colab T4

한 번에 하나씩만 바꾸고, 매번 `docs/실험_기록.md`에 기록한다. 이 표가 발표의 "AI를 이렇게 개선했다" 근거가 된다.

| 버전 | 바꾸는 것 | 예상 시간 | 볼 점수 |
|---|---|---|---|
| v1 | 공개 데이터셋만, `yolo11n`, 100 epochs | 약 1시간 | 공개 test mAP50 / **부산 test mAP50** |
| v2 | 모델 키우기 `yolo11s` | 약 2시간 | 부산 test가 올랐나 |
| v3 | 부산 라벨 사진 100장을 학습에 추가 | 약 2시간 | 부산 test가 크게 오르는지 (지역 적응 효과) |
| v4 | 가장 좋은 설정 + `imgsz=960` 또는 epochs 늘리기 | 2~3시간 | 최종 |

- 실행: Colab에서 `BUSAN_BASE=/content/drive/MyDrive/busan_project` 설정 후 `python 01_merge_datasets.py && python 02_train.py`
- `config.py`의 `RUN_NAME`을 v1, v2 … 로 바꿔야 결과가 덮어써지지 않는다.
- **목표:** 부산 test mAP50 **0.6 이상**. 못 미쳐도 "v1 → v3 개선 과정"을 보여주면 된다.
- 학습이 끝나면 `runs/<버전>/results.csv`로 포스터 그래프 1번을 다시 만든다.

### 3-5. OSM 계단과 비교 (11/17 ~ 11/19) – 새 스크립트 `ai/05_match_osm.py`

같은 계단이 사진 여러 장에 찍히므로 먼저 합치고, OSM 계단 위치와 비교한다.

1. **중복 합치기:** 15m 안의 같은 클래스 탐지는 1개로 (DBSCAN).
2. **OSM 계단과 매칭:** 탐지 위치에서 20m 안에 OSM 계단이 있으면 "일치".
3. 결과 숫자 3개 → 발표·포스터용

| 지표 | 뜻 | 발표 문구 |
|---|---|---|
| OSM 재발견율 | 사진이 있는 OSM 계단 중 AI가 찾은 비율 | "지도에 있는 계단의 N%를 AI가 다시 찾음" |
| **새로 찾은 계단 수** | OSM에 없는데 AI가 찾은 계단 (사진 눈으로 확인한 것만) | **"지도에 없던 계단 N곳 발견"** |
| 새로 찾은 턱 수 | OSM에는 턱 정보가 거의 없음 | "턱 N곳 지도화" |

> "새로 찾은 계단"은 Mapillary 사진을 직접 열어서 진짜 계단인지 확인한 것만 센다. 오탐을 세면 안 된다.

## 4. AI ② 사진 없는 구간 예측 (XGBoost) – 담당 B

### 4-1. 경사도 붙이기 (11/10 ~ 11/14)

DEM이 오면 도로망에 경사를 붙인다. OSMnx 기능으로 몇 줄이면 된다.

```python
import osmnx as ox
G = ox.graph_from_point((35.117, 129.0375), dist=1000, network_type="walk")
G = ox.elevation.add_node_elevations_raster(G, "data/raw/dem/busan_dem_4326.tif")
G = ox.elevation.add_edge_grades(G, add_absolute=True)   # 구간마다 grade, grade_abs
ox.save_graphml(G, "data/processed/walk_graph.graphml")   # 저장 → 시연 때 인터넷 없이 사용
```

- 국토지리정보원 DEM은 좌표계가 다르다 → 먼저 변환: `gdalwarp -t_srs EPSG:4326 원본.img busan_dem_4326.tif`
- **DEM 승인이 11/12까지 안 오면 대체:** Copernicus DEM 30m (가입 없이 바로 받음)
  `https://copernicus-dem-30m.s3.amazonaws.com/Copernicus_DSM_COG_10_N35_00_E129_00_DEM/Copernicus_DSM_COG_10_N35_00_E129_00_DEM.tif`
  (30m라 덜 정밀하고 건물 높이가 섞임 → 발표 때 한계로 언급)
- 완료하면 `server/routing.py`의 `add_slope()` TODO를 이 코드로 바꾼다 (C와 함께).

### 4-2. 학습 데이터 만들기 (11/14 ~ 11/18) – 새 스크립트 `ai/06_edge_features.py`

도로 구간(edge) 하나가 데이터 한 줄이다.

| 종류 | 열 이름 | 설명 |
|---|---|---|
| 특징 | `grade_abs` | 구간 경사 |
| 특징 | `elev_diff` | 양 끝 높이 차이 |
| 특징 | `length` | 구간 길이 |
| 특징 | `highway` | footway / residential / path / service … (계단 `steps`는 **빼고**) |
| 특징 | `neighbor_grade_max` | 이어진 구간들 중 가장 가파른 경사 |
| 특징 | `elev_mean` | 높이 (산복도로일수록 높음) |
| 특징 | `dead_end` | 막다른 길인지 |
| **정답** | `has_stairs` | OSM `steps`이거나 AI ①이 계단을 찾은 구간 = 1, 사진이 있는데 없었던 구간 = 0 |

- **사진도 없고 OSM에도 없는 구간은 정답을 모르므로 학습에서 뺀다** → 이 구간들이 나중에 예측할 대상.
- `highway=steps`를 특징에 넣으면 정답을 그대로 알려주는 꼴이므로 반드시 뺀다.

### 4-3. 학습·평가 (11/18 ~ 11/21) – 새 스크립트 `ai/07_train_predictor.py`

- 모델: `XGBClassifier` (`ai/requirements.txt`에 `xgboost` 추가)
- **지역으로 나눠서 평가:** 시범 지역 서쪽 70%로 학습, 동쪽 30%로 시험. (무작위로 나누면 바로 옆 구간끼리 정답을 베껴서 점수가 부풀려짐)
- 볼 점수: AUC, 계단 재현율(실제 계단 중 맞힌 비율)
- 비교 기준: "경사 10% 넘으면 계단"이라는 단순 규칙보다 나아야 의미가 있다 → **"규칙 0.6 → AI 0.8"** 같은 비교가 발표 그래프가 된다.
- 결과: 사진 없는 구간마다 `stairs_prob` → `data/processed/edge_risk.csv`

### 4-4. 서버에 반영

- `stairs_prob ≥ 0.7`인 구간은 경로 계산에서 "계단 의심(AI 예측)"으로 취급 (출처 표시 `source = "predicted"`).
- 화면에는 "AI 예측 – 현장 확인 필요"로 다르게 표시.

## 6. 유형별 통과 기준

법 기준: 「장애인·노인·임산부 등의 편의증진 보장에 관한 법률 시행규칙」 [별표1]
(접근로 기울기 **1/18 이하**, 지형상 곤란하면 **1/12**까지 / 높이 차이 **2cm 이하**) → [국가법령정보센터](https://www.law.go.kr)에서 **직접 확인 후** 확정

| 장애물 | 일반 | 어르신 | 유아차 | 휠체어 | 관광객(캐리어) |
|---|---|---|---|---|---|
| 계단 | 통과 | 크게 감점 | **불가** | **불가** | 크게 감점 |
| 턱 2cm 초과 | 통과 | 통과 | 감점 | **불가** | 감점 |
| 경사 5.6%(1/18) 초과 | 통과 | 감점 | 감점 | 크게 감점 | 감점 |
| 경사 8.3%(1/12) 초과 | 통과 | 크게 감점 | 크게 감점 | **불가** | 크게 감점 |
| AI 예측 계단 (확률 0.7↑) | 통과 | 감점 | 크게 감점 | 크게 감점 | 감점 |

> AI 예측 계단은 "불가"가 아니라 "크게 감점"으로 둔다. 틀렸을 수 있기 때문. 이것도 발표 포인트("확실한 것과 예측을 구분").

## 9. 막혔을 때 줄이는 순서

뒤에서부터 줄인다. 위쪽은 꼭 지킨다.

1. ✅ **꼭:** OSM 계단 + 경사도로 유형별 경로 (AI 없어도 동작하는 기본)
2. ✅ **꼭:** AI ① YOLO 탐지 + 부산 test 점수 + OSM 비교
3. ✅ **꼭:** 휴대폰에서 3화면 시연
4. ⭕ 가능하면: AI ② XGBoost 예측
5. ⭕ 가능하면: 세 번째 경로, 출입구 5곳 이상
6. ❌ 시간 남으면: 이용자 제보 고도화, 실제 앱 스토어용 앱

> AI ②를 못 하면 포스터의 "안 가본 길까지 판단" 문구를 "사진으로 지도에 없는 장애물까지 판단"으로 바꾼다. 하지 않은 것을 했다고 쓰면 안 된다.

## 10. 본선 시연 시나리오 (3분)

1. (휴대폰) 앱 아이콘 실행 → **유아차** 선택 → 초량역 → 목적지 (미리 정한 장소)
2. 경로 비교: 최단 경로는 계단 2곳, 편한길로는 계단 0곳 (+N m)
3. 계단 아이콘 누르기 → "AI가 Mapillary 사진에서 찾음 (확신도 0.9)" + 원본 사진
4. 같은 출발·도착으로 **휠체어** 선택 → 경로가 또 바뀌는 것 보여주기
5. 목적지 도착 → 출입구 안내 (정문 계단 ✕ / 측면 경사로 ○)
6. (노트북) 장애물 지도 전체: OSM 계단 vs **AI가 새로 찾은 계단** 색 구분

> 시연용 출발·도착 2~3쌍은 미리 정해 두고, 결과 화면을 캡처해 둔다 (서버가 죽으면 캡처로 설명).
